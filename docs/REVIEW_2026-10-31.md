# Review pass, 2026-10-31

Six review agents read the code after the first build: `pr-review-toolkit` code-reviewer, silent-failure-hunter, pr-test-analyzer, type-design-analyzer, comment-analyzer, and a general-purpose security review. This records what they found and what was done. Regression tests for the fixes are in `tests/integration/test_regressions_from_review.py`, `tests/unit/test_validators.py` and `tests/eval/test_eval_integrity.py`.

## Fixed

| Area | Defect | Fix |
|---|---|---|
| Write-back | The attempt cap ran before the "did it land?" check, and counted reads and throttles. A landed write could end `failed`, permanently | Check for a landed write first; count only real mutations |
| Write-back | After a crash, a write that landed and was then edited showed "Nothing was written" | New `outcome_unknown` failure, and the UI says the store may hold the text |
| Agent | Failed runs marked the job done, retries never happened, and `retryable` was dead code | The run finishes as failed, then the error reaches the queue |
| Agent | An unexpected error left runs `running` forever at cost 0 | Every path ends the run |
| Agent | `outcome=proposed` was stored from the model's word | Downgraded to `no_proposal` when no proposal exists |
| Agent | NUL or a lone surrogate from a model crashed the run, including its transcript write | Tool error, and transcript text is scrubbed |
| Agent | Skipping `get_product` skipped the "field too long to rewrite" refusal | Measured at `propose_fix` |
| Cost | Judge calls, cache writes and unpriced models were invisible to the caps | Recorded in `llm_calls`, which the daily cap now sums; unpriced models are charged the highest known rate |
| Judge | `judge_status` came from current config, so a blocked fix read `ok`; malformed output read `ok`; `</data>` closed its data block | Stored per proposal; malformed means unavailable; inputs fenced with a nonce |
| Validators | V03 passed comments, CDATA and unterminated tags that browsers execute | Refused outright |
| Validators | V04 had a fixed TLD list and missed entities; zero-width characters split words past V04, V06, V11 and A13 | Any letters-only TLD, decoded before matching, invisible characters removed or flagged |
| Validators | V05 let `$20`, `20 mg` and `20 GB` pass against "20 oz"; V09 skipped thin descriptions and blocked `500ml` to `500 ml`; V11 blocked on residue already in the source | All corrected |
| Schema | A blocked proposal could never be resubmitted with a corrected citation | Unique index excludes blocked rows |
| RAG | Removing a policy document crashed ingest, retired passages stayed citable, and a stopword query returned arbitrary chunks | Passages retire instead of being deleted; zero vector returns nothing |
| Webhooks | A chunked unsigned body was read into memory before any size check | Counted while reading, verified in a thread |
| Webhooks | Non-object JSON stuck the event at `received`; a bad date header returned 500; a shop mismatch was silent | Marked failed; ignored; logged at ERROR |
| Catalog | Deleted products stayed eligible for paid runs and approval; sync never noticed deletes | Filtered, findings resolved, daily full sync tombstones, and an empty response never wipes the catalog |
| Config | Demo tokens could sit in front of a live store when `ENV` was unset; production could boot on the fixture store; a failed boot printed secrets | Refused in every environment; `hide_input_in_errors` |
| MCP | Tags, SKUs, alt text and evidence came back unfenced; DNS rebinding protection was off in the container | Fence by default with an allowlist of structural keys; protection always on |
| API | No Host check on the local stack; port for the demo webhook came from the client | `ALLOWED_HOSTS`; server socket port |
| Worker | The heartbeat only ran between jobs, so a long job made a healthy worker look dead; the load balancer depended on it | Heartbeat thread; ALB checks `/healthz` |
| Worker | The reaper ignored `max_attempts`, so a job that killed its worker looped forever | Goes dead |
| UI | Errors hidden on non-pending proposals; banner vanished if `/api/meta` failed; failures invisible | Shown; "could not confirm" banner; `/api/ops` notice and a failed filter |
| Eval | A `SKIPPED` report was saved as `PASS`; the test split was not actually frozen; e2e could pass with zero products; unknown suites passed; negative controls did not exist | All fixed, with tests that make the gate fail on purpose |
| Tests | `test_mcp.py` overwrote cluster-wide role passwords used by a running demo | Uses the demo values |

## Not fixed, and why

| Finding | Status |
|---|---|
| MCP HTTP transport has no authentication | Loopback only in compose, not deployed by Terraform. Accepted for a read-only local tool |
| A captured signed webhook can be replayed with a new id | One extra refetch and one event row each, no state change. No rate limit or retention yet |
| Reviewer tokens have no rate limit, lockout or expiry, and the API shares a public listener with webhooks | Needs a WAF rule or a path restriction before real use. ADR-0011 records the cost |
| `variants(first: 25)` and `media(first: 10)` read a partial product on large products | Stays under the query cost limit, whose real figure is unverified. Changes beyond those limits do not mark a proposal stale |
| Job completion does not check the lock owner | Only matters if a job outlives the 10-minute reaper with two workers running |
| `/api/meta` tells anonymous callers the model and adapter | The login page needs part of it. Low value to an attacker, should be trimmed before real use |
| `requirements.lock` has no hashes, and base images use floating tags | Hardening for a real deployment |
| V06 misses synonyms such as "relieves arthritis" | An accepted limit of a word list. Reported as V06 recall on the test split |
| The first v2 test run found `Guaranteed lowest price` also fires V07, which the case's expected set did not declare | Counted as false positives in the frozen report. A label gap, left in place because the split is frozen |

## How the eval's history affects the numbers

Dataset v1's test split was scored by the test-analyzer agent during this review, which reported A03 recall 0.40. So v1 stopped counting as held out. Its wording moved into the dev pools, and new test wording was written for v2 before its first run. Rules were committed first (`5e4c1ba`), the split was frozen next (`7ce3d50`), and the first run followed. That run failed the A13 floor. A13 was not tuned afterwards. It is recorded as a known failure in `eval/gates.yaml`, and it stays visible in every report.
